## 実行手順

### 1. フォーム回答を受け取って整理する

貼られた回答から抜き出す：呼び名／生年月日／出生時間／出生地／いまのモヤモヤ（原文のまま保持）／読んでほしいテーマ／**触れてほしくないこと**。

出生時間の精度を3段階で判定する：**分単位確定／概算（「夕方5時ごろ」等）／不明**。
精度で使える素材が変わる（`natal-reading-design.md` 2-1 の表。概算ならASC・MCへのタイトアスペクトを加点素材から外す、など）。

### 2. 出生地を緯度経度へ変換する

市区町村の代表点でよい（自分の知識で出す。Web検索不要）。ステップ4の確認に含めて誤りを拾う。
**1948〜1951年の5〜9月生まれは日本の夏時間に注意** → `KANTEI_TZ=600` で計算し、その旨も確認に含める。

### 3. 天体計算を実行する

```powershell
cd oshi-uranai/app
$env:KANTEI_BIRTH="1966-12-03 17:00"    # 時刻不明は "1966-12-03 --"（概算は代表時刻で入れる）
$env:KANTEI_PLACE="35.6344,139.5786"    # 緯度,東経
$env:KANTEI_TODAY="2026-08-27"          # 有料のみ＝実行日。無料は設定しない（$env:KANTEI_TODAY=$null）
npx vitest run tests/unit/personal-reading.probe.test.ts --disable-console-intercept
```

出力されるもの：
- 10天体＋ASC/MC＋ドラゴンヘッド／テイル（サイン・度数・プラシーダス／ホールサイン両ハウス・逆行）
- プラシーダスのカスプ12本
- 設計書オーブ準拠のネイタルアスペクト一覧（★＝1度以内タイト）
- ステリウム（10天体で判定）／エレメント・モードの偏り
- 時刻不明時：月の可動域（サイン移動があれば「両方提示の型」への切り替え指示つき）
- `KANTEI_TODAY` 指定時：当日の全天体位置＋トランジット→ネイタルのアスペクト（スロー3度・速い天体2度以内）＋スロー天体の在室ハウス

### 4. データ確認（1回だけ聞く）

出生データ・時刻精度・緯度経度・計算サマリーを提示し、「このデータで進めていいですか」と**1回だけ**確認する。ユーザーが手動データを出したらそちらを優先。

### 5-A. 無料の場合

`oshi-uranai/docs/natal-reading-design.md` を**必ず読み**、以後は全面的にそれに従う：

1. 3章のスコアリングで素材選定（コア4点＋加点素材上位2つ。ステリウムの強み／弱点分岐は3-2-1）
2. 3-4 の型で**処方の候補を2〜3提示**し、星野さんに選んでもらう（候補1つでも確認は必ず挟む）
3. 4-A／4-B の段落構成で1,000字程度（上下200字は許容。1,300字を超えたら削る）
4. 根拠は5章の二段構え（数値を出す条件は5-1）／ハウスの呼び方は6章の辞書から／文体は7章

モヤモヤ欄は切り口の参考にとどめ、本文で引用しない。
参考にする過去鑑定：`oshi-uranai/samples/sample-natal-19661203.md`・`sample-natal-19650507.md`・`reading-natal-19840814.md`

⚠️ **文体の最新基準は、`oshi-uranai/kantei/` にある 2026-09-02 作成の鑑定**（星野さんリライト版。冒頭メタの備考に「文体規範は」とあるもの＝`grep -l 文体規範は oshi-uranai/kantei/*` で1件に絞れる。ファイル名はリポジトリに書かない）。
ハウスは「意味＋番号」表記、アスペクトは角度が主、サインは一般論→当てはめの二段、
内心の声はセリフ改行、行動提案は対句、締めは許可から入る。詳細は設計書 5-1・6章・7-1。
上の3本は**この表記に更新される前**の鑑定なので、構成の参考にとどめ、表記はまねしない。

⚠️ **処方〜締めの書き方の最新基準は、`oshi-uranai/kantei/` にある 2026-10-02 作成の「鑑定文の型・T字版」の最後の4段落**（星野さんリライト。ファイル名はリポジトリに書かない）。
サインの性質は「具体的な手順に落とし込む」まで書く／ハウスの意味語に役割を一言添える（「家や居場所」、自分の土台）／
「全部」を避けて順番の語を入れる（さまざまなことを〜まずは）／「選ぶ」は何を選ぶかまで書き、結果は積み重なる過程で書く／
締めの「価値」は段落1の具体語（収入や自信 など）で回収する。詳細は設計書 7-1(13)。

### 5-B. 有料の場合（6ブロック・約2,000字）

素材選定はスコアリングを使わない。**モヤモヤ起点**で選ぶ：

1. **モヤモヤの分解**：困りごとの中心はどこか／本人の言い回しから**引用候補を原文ママで2つ**抜き出す
2. **ネイタルから、モヤモヤに関係する配置だけ2〜3点**（チャート全部を説明しない）
3. **トランジットから「なぜいまか」に答える1〜2点**（木星〜冥王星のスロー優先。速い天体は添え物）
4. **見立ての候補を2〜3本提示**して選んでもらう：

```
【素材】ネイタル：…／トランジット：…
【見立て候補】
 A 「つまり◯◯ということだと見ます」…（1〜2文で）
 B …
 → どれで書きますか（組み合わせ・修正も可）
```

5. 選ばれた見立てで6ブロックを書く：

| # | ブロック | 字数目安 | 中身 |
|---|---|---|---|
| 1 | 受け取り | 150 | 相手の言葉を**原文ママ引用**して始める。「『◯◯』と書いてくれましたね。」要約しない |
| 2 | あなたの星の土台 | 400 | モヤモヤに関係する配置だけ2〜3点。「こういう星を持って生まれた人」という自己理解の言葉に翻訳 |
| 3 | いまの流れ | 400 | トランジットで「なぜ、いまそのモヤモヤが起きやすいのか」。時期の説明がつくと、それだけで楽になる |
| 4 | 見立て | 500 | 中核。「つまり、あなたのモヤモヤはこういうことだと私は見ます」と**言い切る**。星の話から人の話へ着地させる |
| 5 | 今週からできること | 300 | 小さい行動を**2つだけ**。大きな決断を迫らない |
| 6 | 締め | 250 | 余韻のある言い切り＋質問1往復（納品後2週間以内）の案内 |

**有料の固有ルール：**

- **「触れてほしくないこと」には絶対に触れない**（比喩・遠回しでも）。素材選定の段階で除外する

**見立ての精度（2026-08-27 星野さんフィードバック・初回テストランより）：**

- **因果の順番を断定しない。** 出生図から言えるのは構図まで。「Aが先に細ったからBになった」のような順番の断定は、本人への問いに変換する（例：「私はこの関係の中で、本音をどこまで出せているだろう」）
- **「もともと（出生図）＋いま（トランジット）」の二段で書く。** モヤモヤの正体を出生図側だけに寄せない。両方が重なった場所に置く
- 木星は「満たされる」ではなく**「感情・欲求・期待が大きく動く」**星として書く。心の声をセリフにする（「私、本当はもっとこうしたい」）と本人の感覚に寄る
- **出生図の強い軸は、複数の悩みそれぞれに直接つなげられないか先に検討する**（例：4室天王星・冥王星 vs 10室土星 → 家庭の話だけでなく「役割を優先して生きていくのか」という仕事側の問いにも効く）
- **締めは、その鑑定で使った素材を全部回収する一文で終える。** 出生のテーマとトランジットの両方が畳まれているかを出力前に確認する
- 時期の話は「いま効いている」の範囲で書く。終了時期は計算から自信を持って言えるときだけ大まかに
- 時刻不明・概算なら2-1表の時間非依存素材に寄せる。時刻不明ではASC・MC・ハウスを書かない
- 根拠の見せ方（5章・数値条件5-1）・ハウスの呼び方（6章の辞書）・文体（7章）は無料と共通で `natal-reading-design.md` に従う
- 語り口のベースは oshi-uranai-weekly の共通ガイドライン（短い行で改行／カジュアルな語尾／専門用語の言い換え／文末は言い切り・ですます・体言止めのみ）
