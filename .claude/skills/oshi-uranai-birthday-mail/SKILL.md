# 誕生日メール（星の手紙）作成スキル

## ⚠️ このスキルの立ち位置

- **正は設計書** `oshi-uranai/docs/birthday-reminder-design.md`。型（2章）・読み方（3章 STEP 1〜5・技法の統一ルール）・送るタイミング（5章）はそちらを読んでから書く。このファイルは手順と運用の決まりだけを持つ
- 出力は**下書き**。星野さんが確認してから Gmail で送る（送信はユーザー。Claudeは送らない）
- ⚠️ **個人情報を扱う。** 保存先は `oshi-uranai/birthday-mail/` のみ（.gitignore済み・リポジトリはPUBLIC）。**コミットしない。外部サービスに送らない**
- 鑑定（2,000円）とは別物：ハウスは**ホールサイン**、出生図ではなく**太陽回帰図**を読む。`personal-reading.probe` は使わない
- v1（`mail/parts.md`・`mail/birthday_mail.py`）は使わない

---

## 実行手順

### 1. 材料を集める

| 項目 | 取り出し元 |
|---|---|
| 呼び名・生年月日・出生時刻・出生地 | 鑑定済みの人は `oshi-uranai/kantei/` の鑑定文の冒頭メタブロック。それ以外は統合名簿／フォーム回答を貼ってもらう |
| いま住んでいる場所 | 統合名簿の「現住所」列。**空なら出生地で計算**し、根拠欄で返信をお願いする（下の 5.） |
| 本人の悩み・関心 | 鑑定のモヤモヤ欄や星野さんの一言（例：「いま仕事に悩んでいる」）。あれば**具体例をそこへ寄せる** |
| 送る日（ASOF） | 登録直後の回＝送る日／誕生日の回＝誕生日 |

緯度経度は市区町村の代表点でよい（自分の知識で出す）。1948〜1951年の夏時間出生は `BDAY_TZ=600`。

### 2. 計算する

```powershell
cd oshi-uranai/app
$env:BDAY_BIRTH="1990-01-15 08:30"   # 時刻不明は "1990-01-15 --"（＝簡易版）
$env:BDAY_PLACE="34.69,135.50"       # 出生地の緯度,東経
$env:BDAY_STAY="35.68,139.69"        # いま住んでいる場所（不明なら行ごと省略）
$env:BDAY_ASOF="2026-10-13"
npx vitest run tests/unit/birthday-letter.probe.test.ts --disable-console-intercept
```

出力の STEP 1〜4 の材料を見て、設計書3章の手順でテーマ・可能性・課題・来年・問いを1つずつ選ぶ。
**時刻不明（簡易版）では月・ASC・MC・回帰図の太陽のハウスを使わない**（設計書3章の表）。

### 3. 下書きを書く

- 型：件名 → 呼びかけ → 前置き（登録直後の回だけ）→ キャッチコピー1文 → 5見出し → 結び「では、次は来年のM月D日、誕生日の朝に。」→ 根拠 → フッター
- 見本：`oshi-uranai/birthday-mail/20261013_かなこ_誕生日メール_今年分.txt`（最初の1件・星野さんの直しが入った完成形）
- ハウスは番号を出さず `natal-reading-design.md` 6章の意味の語で。天体には役割を一言添える（「慎重さの星の土星」）
- **語り口はやわらかく。** 星野さんの直しの傾向：
  - 抽象語は**具体例**に置き換える（「輪」→「職場の同僚、同じ仕事をしている人、講座で一緒に学ぶ人、SNSでつながる人」）
  - 「決まりごとに戻る」より「心地よいと感じる小さな習慣」。例は日常の動作で（好きなお茶をいれる、いつもの時間に眠る）
  - ハードルを下げる一言を添える（「それくらいのことで大丈夫です」）
  - 話題が切り替わる所にはつなぎの言葉を入れる（「仕事だけでなく、」）
- 鑑定を受けた人なら、鑑定文で読んだ本人の強みにひと言つなげてよい（例：「調べたことを整理して、人にわかりやすく伝えるのが得意な人」）。出生図の読み直しはしない
- 来年は予測しない。次の回帰図に出る**象徴的なテーマ**と「そのために今年できること」
- 誕生日の回で案内を添えるときは本文のあと罫線（⸻）の下。登録直後の回は売らない

### 4. 字数を数える

本文（5見出しの中身。キャッチコピー・結び・根拠・フッターは除く）が **750〜950字** に収まっているか、Pythonで数えて報告する。超えたら削る候補を示してから削る。見出しごとの目安は設計書2章（150〜200字、問いは80〜120字）。

### 5. 根拠欄

プロフェクション（ハウス・サイン・年の支配星）／太陽回帰図（日時・ASC・太陽と月のハウス）／本文で使った天体の配置／来年のプロフェクション。末尾に計算した場所を1行：

- 現住所で計算した：「※太陽回帰図は、いまお住まいの場所（◯◯市）で計算しています。」
- 出生地で代用した：「※太陽回帰図は、生まれた場所（◯◯）で計算しています。いまお住まいの場所が違えば、このメールに返信で教えてください。来年から反映します。」

現住所があとから分かったら、`BDAY_STAY` を変えて再計算し、出生地版と**差分**を見る（サイン・ハウスが同じなら本文はそのまま、根拠欄の注記だけ差し替え）。

### 6. 保存と完了

- **保存先**：`oshi-uranai/birthday-mail/`（この外に置かない）
- 翌年も使う計算値（出生データ・出生地と現住所の座標）は `oshi-uranai/birthday-mail/_計算メモ.md` に1人1行で残す。**STATE.md など公開ファイルには書かない**
- **命名**：`YYYYMMDD_呼び名_誕生日メール_今年分.txt`（作成日）
- 「調整したい箇所はありますか？」と聞き、直しが入ったら 4. の字数チェックをやり直す
- 確定したら `oshi-uranai/docs/STATE.md` の誕生日メールの記述を更新する（進み具合だけ。出生データ・住所・座標は書かない）
- 送信後は統合名簿の「登録直後メール」列（誕生日の回は送信日）に日付を入れるよう星野さんに伝える

### このスキルの対象外

- メールの送信・予約送信（Gmailで星野さんが行う）
- 名簿・フォーム・GAS（`gas/build_meibo.gs`）の変更
- 出生図リーディングの鑑定文（`oshi-uranai-kantei`）
