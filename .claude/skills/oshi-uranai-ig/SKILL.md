# 推しの占い子 Instagram メイン投稿 生成スキル

## ⚠️ 重要：このスキルは一度だけ実行すること。ループや繰り返しは禁止。

**最初にoshi-uranai/docs/STATE.mdを読み、現在の決定を確認してから次の2つを読むこと。**
1. `oshi-uranai/docs/instagram-operation-design.md` … 仕様の本体。SKILL.mdと矛盾したら設計書が正
2. `references/voice.md` … 文体規則。**これを読まずに本文を書き始めない**

---

## このスキルが守る一行

**「星座名から企画を始めない。人間の感情から始める。」**

「乙女座新月です」ではなく、「ひとつだけ、整えてみる」から入る。
星の情報は捨てないが、**階層を下げる。**

## 実行手順

### 0. カレンダーで枠を確認する

```bash
cat oshi-uranai/docs/posting-calendar.md
```

- **その日に何を出すかは、原則ここに決まっている。** 決まっていなければ先にカレンダーを埋める。
- 1か月ぶんの素材を出し直すとき（月初・カレンダーが空のとき）：

```bash
python .claude/skills/oshi-uranai-ig/scripts/month_astro.py --month YYYY-MM
```

  月相・サイン移動・逆行ステーション・**アスペクトの正確日＋3度圏の滞在日数（速度フィルタ判定つき）**が出る。
- **正確日が木・金でも、定例は月曜に出す。**（設計書2章）後ろにずらさず、当日はストーリーズで刺す。

### 0-2. カード回のときは、ここで分岐する

**カードだけを扱う回は、天体計算（手順1・2）を行わない。** 代わりに次の順で作る。

1. **ユーザーに実際に引いてもらう。** 質問例「今日、取り組むことへのヒントは？」
   → 引いたカード名とデッキを記録してから原稿に入る。**引いていないカードを書かない**（③の素材と同じ扱い）。
2. 本文は**この順で運ぶ**：気になった部分 → 絵のどこからそう感じたか → **基本の意味** → 今日試すこと
3. **意味・解釈・使い方を混ぜない。** 「カードの基本の意味」と「私はこう読んだ」と「今日どう使うか」を分けて書く。
4. 基本の意味と、私の読み方・使い方を分けて書く。（二人組の設定は2026-09-29に保留）
5. 1枚目の**帯**には星の出来事の代わりにカード名を置いてよい（8〜12字・ジャンル名は入れない）。
6. 最終枚は通常回と同じ2行固定。

星とカードを同じ回で扱ってもよいが、**主役はどちらか一方**に絞る（1投稿に詰め込まない）。

### 1. 天体データを実測する

```bash
python .claude/skills/oshi-uranai-weekly/scripts/fetch_astro.py --week YYYY-Wnn
```

- 対象週を間違えない。ユーザーが日付を言ったらその週に `--week` で合わせる。
- **astro.com等のWebFetch読み取りは禁止**（星座記号を誤読するため）。データ源は本スクリプトかユーザー提供の2択。
- ユーザーが手元データを持っていれば、そちらで上書きする。
- **曜日を設計書の表から読まない。必ず実測する**（`python -c "import datetime;print(datetime.date(Y,M,D).weekday())"` または fetch_astro の見出し行）。過去に設計書のカレンダーが1日ずれていた。

### 2. 「人間の感情」を1つに絞る

出力されたアスペクトから、**その週いちばん強く出る感情を1つだけ**選ぶ。
運用設計書2章の速度フィルタを優先し、持続タグだけで主役を選ばない。**2つ以上を1投稿に詰めない。**

翻訳の目安（`references/aspect_meanings.md` も参照可）：

| 配置 | 起こりやすい感情 |
|---|---|
| 火星×土星 スクエア | 進みたいのに進めない／急ブレーキ／焦り |
| 太陽×天王星 スクエア | 今まで平気だったことが急に嫌になる |
| 新月（乙女） | ひとつだけ整えたい／点検したい |
| 満月（牡羊） | で、私はどうしたい？／出したい |
| 金星×冥王星 スクエア | 手放せない関係・執着 |
| 水星×天王星 | 考えがまとまらない／急に思いつく |

テーマ例のストック：頑張ってるのに進まない／ひとつだけ整えてみる／「もういいかな」と思っていること／考えすぎて動けない／人に合わせる？自分を通す？／私は本当はどうしたい？／モヤモヤを言葉にする／今まで平気だったことが急に嫌になったとき

### 3. 過去の投稿を確認する

`oshi-uranai/ig-main/` の直近3本を読み、以下が重ならないようにする：

- **1枚目のコピーのトーン・語彙**（「整える」「動き出す」が毎回続くと陳腐化する）
- **受け皿（⑥）の型**（前回と同じ型を使わない）
- **③で出した自分の面**（同じ面が3回続かない。4本に1本は軽い回）

### 4. ③④の素材をユーザーに聞く（1回だけ）★最重要

**ここは捏造できない。そして、ここが空のまま先に進むとAI臭い文章になる。**

2026-09-07のフィードバックで原因が特定された：素材がある①②は「まだいい」と評価され、**素材ゼロで埋めた⓪⑤⑥だけが「当たり前のことしか言っていない」と却下された。** 素材がないと、何にでも当てはまる抽象語で埋めてしまうため。

**したがって、⓪⑤⑥を③より先に書かない。** ③の素材が取れてから、③に出てきた具体的な名詞・動詞を流用して⓪⑤⑥を書く。

星の読み（①②）と、③の切り口候補を提示したうえで、1回だけ聞く：

> 今週のテーマは〔感情〕です。③に使えそうな最近の出来事はありますか？
> （なければ、その週に撮った写真から逆算します）

ユーザーが「任せる」と言った場合のみ、**推測とわかる形で下書きし、事実確認を明示的に求める。**

### 5. 6ブロックを一度に生成する

| # | ブロック | 目安字数 |
|---|---|---|
| ⓪ | 掴み（**人間の言葉のまま。星の話をしない**） | 20〜50字 |
| ① | 今の星の流れ | 60〜100字 |
| ② | 日常の言葉に翻訳 | 100〜150字 |
| ③ | 私に起きたこと（固有名詞を1つ入れる） | 150〜250字 |
| ④ | 私はどう読んだか ← **一番時間をかける** | 150〜250字 |
| ⑤ | あなたの場合は（問いは1つに絞る） | 100〜150字 |
| ⑥ | 持ち帰り（受け皿） | 80〜120字 |

**⓪⑤⑥は③の言葉で書く。** ③に「メール」「リスト」「36本」が出たなら、⑤⑥もその語彙で書く。新しい抽象語を持ち込まない。素材が足りず抽象語しか置けないブロックは、**抽象語で埋めずに空欄のまま出す。** 空欄はミスではない。

**③→④→⑤の接続は必ずこの形にする：**
「私はこうだった」→「これって、こういう星の使い方ができる」→「じゃあ、あなたの場合は？」

**⓪は毎回入れる。2枚目に星の解説を置かない**（1枚目＝人間の言葉／2枚目＝占星術用語、で階層が逆転しスワイプが切れるため）。
型は**告白型**（私の出来事）と**言い当て型**（読者の状態）の2種類。同じ型を3回続けない。
⓪で明かした話は③で繰り返さず、③は続き（具体・細部）から書く。

### 6. 1枚目のコピーを決める（**3層**・設計書6章）

| 層 | 中身 | 位置 |
|---|---|---|
| **大** | 人間の言葉（**24字以内**・2〜3行・句点で切る） | 写真の余白に合わせて毎回変えてよい |
| **帯** | その回の星の出来事を**日本語で8〜12字**（例：`乙女座新月` `天王星逆行開始` `火星×土星スクエア`） | 大コピーの行間に挟む。挟めない回は大コピーの下 |
| **英字** | 星のキーワードと日付（例：`MARS × SATURN` / `SEP 01`、`NEW MOON IN VIRGO`） | **毎回同じ位置に固定** |

- 帯は**1投稿に1本だけ**。イベントが複数ある回でも主役の1つに絞る。
- 帯に**「星読み」「占星術」「占い」というジャンル名を入れない**（表紙で名乗らない）。
- 帯に**色は使わない**。白ベタに黒文字か、写真から拾った濃いグレーに白文字。
- 案を**3つ**出して選んでもらう（大コピー3案＋その回の帯1本）。

### 7. 写真の指示を出す

**AI画像は使わない。** 撮る／ストックから選ぶための指示を、被写体・光・時間帯・外し方の4点で書く。

「生活の断片 × 柔らかな光 × 低彩度 × 少し曖昧 × 人の気配」。
ブレ・甘いピント・逆光・変な構図を許容する。**綺麗に撮ろうとしない。**

### 8. キャプションとハッシュタグ

設計書7章の型に従う。冒頭2行に結論を置かず、引っかかりを置く。
ハッシュタグ10〜15個。固定4つ＋可変。**巨大タグは入れない。**

### 9. 文体チェックを通す

```bash
python .claude/skills/oshi-uranai-ig/scripts/check_ig.py oshi-uranai/ig-main/YYYY-MM-DD_スラッグ.md
```

`✕` が出たら直してから出す。`△` は判断。**通っても最後に声に出して読む**（読んで言いにくい文＝書き言葉になっている）。
チェッカーが見るのは `references/voice.md` の一部だけ。抽象名詞・構造予告・対句の連発・敬体の詰問・三点列挙・文末の単調さ。

### 10. 保存する

**原稿は作業ごとに1ファイル（2026-09-30）。** 同じ日にフィード投稿とストーリーズがあれば2ファイルに分ける。ファイル名＝`YYYY-MM-DD_種類_タイトル.md`（種類＝投稿／ストーリーズ／リール）。ストーリーズが複数日にまたがるなら日ごとに分ける。Googleカレンダーも同じ単位で1作業1予定（色＝ブルーベリー）。


`oshi-uranai/ig-main/YYYY-MM-DD_スラッグ.md` に、1枚目コピー案／6ブロック／写真指示／キャプションをまとめて保存する。

## 禁止事項

- 星座名を1枚目の主役にする
- ③で終わる（「私を占ってみました」型）
- 予言口調・吉凶断定・専門用語の羅列
- 1投稿に複数のアスペクトを詰め込む
- 通常回の最終枚に鑑定案内を常設する（告知回のみ追加可）
- 366日誕生日投稿の生成（ペンディング中）
- **③の素材がないまま⓪⑤⑥を書く**（AI臭の最大の原因）
- **抽象名詞を読者の生活の主語にする**（「埋めようとしている空白」「やる気より先に順番がいる」）
- **構造を予告する**（「聞きたいのは一つです」「大事なのは」）
- **①②③の番号列挙**で受け皿を書く
- **引いていないカードを書く**／カードの意味と自分の解釈を混ぜて書く
