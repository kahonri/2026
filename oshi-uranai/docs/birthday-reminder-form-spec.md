## 質問（8問）

### Q1. お名前・呼び名 ★必須
- 形式：記述式（短文）
- 説明：`メールでの呼びかけに使います。本名でなくてかまいません。`

### Q2. 生年月日 ★必須
- 形式：**日付（年を含む）**
- 説明：`年まで教えてください。ここが分かると、この1年に何が来るか（木星と土星）まで出せます。`

### Q3. 生まれた時間帯
- 形式：ラジオボタン
- 選択肢：`朝（4時〜10時ごろ）` / `昼（10時〜16時ごろ）` / `夕方〜夜（16時〜22時ごろ）` / `深夜（22時〜4時ごろ）` / `わからない`
- 説明：`だいたいで大丈夫です。わからなければ「わからない」で。`

### Q4. 正確な出生時刻（母子手帳などで分かる方）
- 形式：記述式（短文）
- 説明：`例：14:35　分かる方だけで大丈夫です。ここまで分かると読めることがさらに増えます。`

### Q5. 生まれた場所
- 形式：記述式（短文）
- 説明：`市区町村まで（例：東京都世田谷区）。海外の方は国と都市名を。`

### Q6〜Q8. 推しの誕生日（1〜3）
- 形式：記述式（短文）×3問
- 質問文：`推しの誕生日①` / `②` / `③`
- 説明（①のみ）：`名前と誕生日を書いてください（例：◯◯ 8/31）。推しの誕生日が近づいたらお知らせします。`
- 説明（②③）：`いれば。`

### Q9. 配信への同意 ★必須
- 形式：チェックボックス（1項目・必須）
- 選択肢：`誕生日のお知らせメールを受け取ることに同意します`
- 説明：`いただいた情報は、誕生日のお知らせと鑑定のご案内にのみ使います。第三者に渡すことはありません。配信はいつでも停止できます。`

```

数日以内に、いま動いている1年のぶんをお送りします。
そのあとは毎年、誕生日の朝に。
推しの誕生日を登録してくださった方には、その少し前にも。
```

> **2026-09-14 改訂。** 2点直した。
> - 旧文面は「次のあなたの誕生日の朝に」だけで、**登録直後メールに触れていなかった**
> - 旧文面の「インスタで毎日、誰かの誕生日の話をしています」は事実と違う。
>   **366日誕生日投稿は凍結中**（STATE §5）。現在の投稿は週1＋新月満月
> - 「すぐ」ではなく「**数日以内**」と書く。名簿20件までは手動送信なので、即時を約束しない。
>   **冒頭の説明文もこの文言に揃えてある**（2026-09-14）

## スプレッドシート側の追加作業

フォームが書き出すシートに、手で3列足す。

### ① 誕生月日 → 不要（2026-08-27 撤回）

当初ここに `=ARRAYFORMULA(IF(C2:C="","",TEXT(C2:C,"MM-DD")))` を置く指示を書いていたが、
**この列は作らないこと。**

- `build_meibo.gs` が `生年月日` から `誕生月日` を自前で計算して `統合名簿` に書く。二重管理になる
- 列番号（C列）を直接指すため、フォームを編集すると壊れる
- 実際に、フォームの質問を並べ替えたあと `#REF!` になった（2026-08-27）

シート上で目視したいだけなら、GASが出す `統合名簿` タブを見る。

### ② 配信停止

見出し `配信停止`。停止依頼が来たら `済` と手入力。GAS側でこの行を除外する。

### ③ 備考

見出し `備考`。手動運用のあいだのメモ用。

### シートの共有設定

**生年月日＋メールは個人情報。** 共有はオフ（自分のみ）のまま。
リンクを知っている人が閲覧、にしない。

## 公開後にやること

1. フォームのURLを短縮しておく（インスタのプロフィールに置く）
2. フィードCTAを週1〜2回このフォームへ向ける（設計書 9章のコピー）
3. 名簿20件までは手動送信で回す。GASはそのあと（設計書 11章）

### 登録が入ったときの手順（手動運用）

```
1. 名簿シートを開く（links.md）→ 拡張機能 → Apps Script → buildMeibo を実行
2. 統合名簿タブから、その人の 呼び名／生年月日／メールアドレス を控える
3. python oshi-uranai/mail/birthday_mail.py --welcome --birth YYYY-MM-DD --name 呼び名 --email アドレス
4. 出てきた本文に赤入れして、Gmailからそのまま送る
```

**待たせない。** 登録直後メールをバッチに乗せると、当日登録した人が1年待たされる（設計書§4）。
