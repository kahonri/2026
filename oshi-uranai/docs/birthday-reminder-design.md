## 1. サービス概要

誕生日を起点に、これから1年のテーマと、次の1年へつながる星の流れを読み解く無料のメール鑑定。
未来を決めつけるのではなく、今の自分が何を大切にし、どんな選択をしていきたいのかを考えるヒントを届ける。

| 項目 | 内容 |
|---|---|
| 鑑定文 | **750〜950字**（キャッチコピー＋5つの見出し。根拠・フッターは字数に含めない） |
| 対象期間 | **直近の太陽回帰から次の太陽回帰まで（当年）＋その次の1年のテーマ（予告）**。暦年の1〜12月ではない |
| 必要な情報 | 生年月日（必須）／出生時刻・出生地／**現在お住まいの場所（任意・2026-10-13 出生図リーディングのフォームに追加）** |
| 申し込みの入口 | **出生図リーディング（2,000円）のおまけとして稼働中**（受付フォームの「誕生日リマインド」にチェック）。**単独の登録フォーム（A）はペンディング**（2026-10-13 星野さん確認） |
| 作り方 | **計算はスクリプト、本文は毎回Claudeが1人ずつ書き、星野さんが確認して送る**（2026-10-13 決定。部品の自動組み立ては廃止） |
| 価格 | 無料（登録者のみ） |

## 2. 鑑定文の構成（固定）

見出しと順番は全員同じ。中身だけを個別化する。

| 見出し | 内容 | 字数 |
|---|---|---|
| （冒頭）キャッチコピー | その年を象徴する一文。例：「自分の価値を、これからの暮らしの土台にする1年。」 | 1文 |
| ■ 今年のテーマ | 1年を象徴するテーマと背景 | 150〜200字 |
| ■ 今年、広がる可能性 | 生かしたい強み・追い風 | 150〜200字 |
| ■ 今年、意識したいこと | 課題・見直しのポイント | 150〜200字 |
| ■ 来年につながる星の流れ | 次の年のテーマと、そのために今年できること | 150〜200字 |
| ■ 星からの問いかけ | 自己理解につながる問い | 80〜120字 |

- 本文は専門用語を極力使わない。ハウスは番号を出さず、`natal-reading-design.md` 6章の**意味の語**で書く（例：「『日々の仕事や習慣』の場所」）
- 天体は「広げる星の木星」「慎重さの星の土星」のように役割を一言添える
- 本文のあとに **「──この手紙の根拠」**を数行置く（プロフェクション・回帰図の主要配置）。自分で読む練習の入口（講座への導線）。字数には数えない
- 来年の運勢を「予測」しない。**次年度のチャートに現れる象徴的なテーマを紹介する**位置づけ

## 3. 占星術の鑑定ルール（内部設計）

### STEP 1｜今年の中心テーマ
- アニュアル・プロフェクションのハウスと年の支配星、太陽回帰図の太陽のハウスを確認する
- 両者に共通するテーマを優先。異なる場合は「今年の主題」（プロフェクション）と「その主題が現れやすい場面」（回帰図の太陽）に整理する
- 年の支配星の回帰図での状態（ハウス・品位・アスペクト）で、その1年の進み方の質感を足す

### STEP 2｜広がる可能性を一つ
- 木星・金星の配置、年の支配星の状態、太陽やASC支配星との主要アスペクトを確認する
- 吉星があるから良い、とは判断しない。ハウスや支配関係も踏まえ、**具体的なテーマを一つ**選ぶ

### STEP 3｜意識したいことを一つ
- 土星・火星、年の支配星への強いアスペクト、必要なら外惑星との関係を確認する
- 不安をあおらない。**どんな姿勢で向き合うとよいか**を伝える

### STEP 4｜次の年への橋渡し
- 次年度のプロフェクションと、次回の太陽回帰図の主要配置を確認する
- 次の年のテーマを一つ選び、「**そのために今年できること**」を導く

### STEP 5｜自分への問い
- 今年のテーマと次年度への橋渡しから、読者自身が答えを見つけられる問いを一つ作る
- Yes／Noで終わらず、価値観や望みを考えられる問いにする

### 技法の統一ルール（2026-10-13 確定）

| 項目 | ルール |
|---|---|
| プロフェクション | 出生図の**ホールサイン**。年齢÷12の余り＋1 ハウス。年の支配星は**伝統的支配星**（外惑星は使わない） |
| 太陽回帰図のハウス | **ホールサインに統一**（プロフェクションと同じ数え方にそろえ、出生時刻の有無で仕組みを分けないため。鑑定〔2,000円〕はプラシーダスのままで、別商品として扱う） |
| 計算する場所 | **いま住んでいる場所**（フォームの任意項目）。空なら出生地で計算し、根拠の末尾に「◯◯で計算しています。違えば返信で教えてください」と前提を書く |
| 次年度の回帰図 | 同じ場所を仮の場所として計算する（前提は上と同じ一文で示す） |
| 品位 | 本来の座・高揚・障害・下降の4つだけ見る |
| オーブ | 回帰図内のアスペクト：太陽・月がからむ6度、その他5度 |

### 出生時刻が不明な人＝簡易版（2026-10-13 決定）

**見出し・字数・送り方は通常版と同じ。** 読む材料だけが変わる。

| | 通常版（時刻あり） | 簡易版（時刻不明） |
|---|---|---|
| プロフェクションの起点 | アセンダントのサイン | **出生の太陽のサイン** |
| 回帰図のハウスの起点 | 回帰図のアセンダント | **出生の太陽のサイン** |
| 回帰図の太陽のハウス | 使う（STEP 1） | 使わない（常に1ハウスになるため）。STEP 1はプロフェクションだけで決める |
| 月 | 使う | **使わない**（時刻が不明だと回帰の瞬間が最大で半日ずれ、月は約6度ずれる） |
| アセンダント・MC | 使う | 使わない |

## 4. 無料と有料の境界（2026-10-13 現行の商品に合わせて書き直し）

| | 誕生日メール（無料） | 自分解説書＝出生図リーディング（2,000円） | 自己理解講座（将来） |
|---|---|---|---|
| 何がわかる | **今年の流れ**と来年への橋渡し | **生まれ持った性質**（得意・苦手・対処法） | **自分で読めるようになる** |
| 中身 | テーマ・可能性・課題・来年・問い | 出生図の読み解き・約1,000字 | 星読みとタロットの基礎＋ワーク |

無料で重要な内容を意図的に隠さない。無料＝今年の全体像、有料＝その人の生まれ持ったものの詳細、という種類の違いで分ける。
（原案の「相談テーマ別・重要な時期・具体的な選択肢」は休止中の5,000円鑑定の中身。再開するときにこの表へ戻す）

## 5. 送るタイミング

| タイミング | 送るもの |
|---|---|
| **登録した直後**（誕生日が過ぎている／まだ先、どちらでも） | **直近の太陽回帰からの1年ぶん**の手紙。冒頭に「誕生日の朝を待たずに、いま動いている1年のぶんを」の一言 |
| **毎年、誕生日の朝** | その日に始まる1年ぶんの手紙 |

- 登録直後は待たせない（v1の2版で「当日登録した人が1年待たされる」失敗あり）
- 登録直後の回は売らない。誕生日の回で案内を添えるときは、本文を閉じたあと**罫線（⸻）の下**に置く（祝いと売りを混ぜない。v1から継続）
- 鑑定の受付フォームで「誕生日リマインド」にチェックした人も同じ扱い（`natal-reading-2000-ops.md`）

## 6. 作る手順（1人ぶん）

```powershell
cd oshi-uranai/app
$env:BDAY_BIRTH="1990-01-15 08:30"   # 時刻不明は "1990-01-15 --"
$env:BDAY_PLACE="34.69,135.50"       # 出生地の緯度,東経
$env:BDAY_STAY="35.68,139.69"        # いま住んでいる場所（空なら省略＝出生地で計算）
$env:BDAY_ASOF="2026-10-13"          # 登録直後＝送る日／誕生日の回＝誕生日
npx vitest run tests/unit/birthday-letter.probe.test.ts --disable-console-intercept
```

出力：通常版／簡易版の判定・対象期間（回帰の瞬間〜次の回帰）・年齢／STEP 1〜4の材料（プロフェクション、年の支配星の出生と回帰図での位置・品位、回帰図の天体とハウス、木星・金星・土星・火星、年の支配星と太陽〔とASC〕へのアスペクト、来年のプロフェクションと回帰図）。

1. 上を実行 → Claudeが STEP 1〜5 で材料を選び、2章の型で下書き（`birthday-mail/` に保存。個人情報なので .gitignore で除外済み。リポジトリの公開部分に書かない）
2. 星野さんが確認 → Gmailから送る（貼り付けは `Ctrl + Shift + V`。1行30字前後・句点で改行）
3. 統合名簿の「登録直後メール」列（誕生日の回は送信日）に日付を入れる

計算部品：`app/src/lib/solar-return.ts`（太陽回帰の瞬間・プロフェクション・品位）／テスト `app/tests/unit/solar-return.test.ts`。天体計算をTSへ一本化する方針どおり、Python（`mail/birthday_mail.py`）は使わない。

**月初に、その月に誕生日が来る人を統合名簿から拾い**、誕生日の朝に届くよう1人ずつ作る（名簿20件まではGmailの予約送信で手動。GASでの自動配送は名簿が増えてから考える）。

## 7. データ（フォームと名簿）

- 登録フォーム・回答シート・統合名簿のURLとIDは `links.md` だけに書く
- 名簿はGAS `buildMeibo()`（`gas/build_meibo.gs`）が、登録フォーム（A）と鑑定の受付フォーム（B・C）のチェックありの人を集める
- **出生図リーディングの受付フォーム（C）に「現在お住まいの地域」を任意で追加済み（2026-10-13 星野さん）**。`build_meibo.gs` は統合名簿の「現住所」列に出す（見出しの表記ゆれは `pick_` で吸収）
- 単独の登録フォーム（A）はペンディング。再開するときは同じ項目を足す（`birthday-reminder-form-spec.md` Q5-2）
- オプトインのチェックは必須にしない（特定電子メール法・v1から継続）

## 8. 法務・プライバシー（v1から継続）

- オプトインの証跡＝フォームの同意チェックと登録日時
- 全メールのフッターに送信者表示と配信停止の方法
- 生年月日＋メールは個人情報。シートの共有範囲を絞る
